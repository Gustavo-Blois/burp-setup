# burp-setup

A versioned Burp Suite setup (config, extensions, runtimes) plus the CLI tools, so a fresh
machine (macOS or Linux) ends up with Burp running and all 15 extensions already loaded, no
BApp Store clicking.

## What's in git

```
manifest/extensions.json    source of truth for the extensions (how each one is obtained)
manifest/cli-tools.json     CLI tools and how to install each one
extensions/                 the extension files (.jar via Git LFS, .py as text)
bootstrap.sh                rebuilds everything: ./bootstrap.sh [all|jython|ext|cli|config|doctor]
launch.sh                   starts Burp with the portable config (leaves ~/.BurpSuite alone)
.gitattributes              *.jar goes through Git LFS
```

Generated by bootstrap and kept out of git: `runtimes/` (jython, downloaded from Maven), `bin/`
and `tools/` (CLI binaries and build sources), `config/user-config.json` (absolute paths for the
current machine).

## Prerequisite: Git LFS

The extension jars (turbo-intruder alone is 50 MB) are stored with Git LFS, so clones stay small.
Install it once per machine before cloning:

```bash
brew install git-lfs     # macOS. Linux: pacman/apt install git-lfs
git lfs install
```

## Prerequisite: Burp Suite itself

Burp Suite is commercial/licensed software from PortSwigger, so the jar isn't in this repo — you
need it installed separately: https://portswigger.net/burp (Community is free, no license needed).

`launch.sh` auto-detects it in the usual install locations (`/Applications/Burp Suite*.app` and
`~/Applications/...` on macOS, `~/BurpSuite/`, `/opt/BurpSuite*/` on Linux), falling back to
Spotlight (`mdfind`) on macOS and a disk search otherwise. If it still can't find it — a custom
install path, for instance — point it at the jar directly:

```bash
export BURP_JAR=/path/to/burpsuite.jar
./launch.sh
```

## On a new machine

Clone it wherever you want. The scripts locate themselves, so the location doesn't matter.

```bash
git clone https://github.com/Gustavo-Blois/burp-setup.git burp-setup
cd burp-setup
./bootstrap.sh all      # jython, extensions, CLI, config
./launch.sh             # opens Burp with the 15 extensions loaded
```

Add to PATH. `./bootstrap.sh doctor` prints these lines filled in with the actual repo path:

```fish
# fish
set -gx PATH $PATH (pwd)/bin (go env GOPATH)/bin ~/.local/bin
```
```zsh
# zsh (default on macOS)
export PATH="$PATH:$(pwd)/bin:$(go env GOPATH)/bin:$HOME/.local/bin:$HOME/.cargo/bin"
```

## Extensions (15)

All of them load without touching the BApp Store. The `source` field in the manifest says how
each one is obtained:

- `local-cache` (11): jars and py files kept in the repo, captured from `~/.BurpSuite/bapps/`.
  Autorize, Param Miner, Turbo Intruder, Logger++, GAP, Wsdler, JWT Editor, PwnFox,
  Copy as FFUF Command, Decompressor, Burp Bounty (Scan Check Builder).
- `download` (2): a `.py` fetched from GitHub by bootstrap. 403 Bypasser, JS Link Finder.
- `build` (2): Java compiled from source with `javac`, no gradle. Flow, Reflector.
  The jar is committed (LFS) as the fast path. If it's missing, `./bootstrap.sh ext` rebuilds it:
  clones the repo, downloads `burp-extender-api`, compiles with `--release 17`, and packages it.

## CLI tools

`./bootstrap.sh cli` installs whatever is missing: httpx, nuclei, waybackurls, gau (go); waymore,
arjun (pipx); x8 (release binary on Linux, `cargo install` on macOS); sqlmap (git clone plus a
wrapper); screen (brew on macOS, already present on the system otherwise, pacman/apt on Linux).

Heads up: there's a shell alias `gau='git add --update'` that shadows the real `gau` in `~/go/bin`.
Drop the alias or call gau by its full path.

### macOS vs Linux

bootstrap detects the OS and package manager (brew, pacman, apt):

- x8: Linux uses the prebuilt release binary; macOS compiles it with `cargo install x8` (there's no
  macOS binary in the release), so it needs rustup/cargo.
- screen: macOS ships `/usr/bin/screen` already; otherwise `brew install screen`.
- Burp: on macOS `launch.sh` finds the jar inside `Burp Suite *.app` and uses the bundled JRE when
  there's no `java` on PATH.

## How the config stays portable

The config is not a fixed snapshot. `bootstrap.sh config` generates `config/user-config.json` from
`manifest/extensions.json`, including every extension whose file exists under `extensions/<id>/`,
with absolute paths for the current machine and the jython in `runtimes/`. `launch.sh` passes that
file with `--user-config-file`, so Burp loads the extensions from the repo without relying on the
machine's `~/.BurpSuite`.

## Adding an extension later

Installed something new from the BApp Store and want it versioned? Grab its uuid under
`~/.BurpSuite/bapps/`, add a `source: local-cache` entry to the manifest, then run
`./bootstrap.sh ext` (copies it from the cache into the repo) and `./bootstrap.sh config`.
